# 데이터, 공개 범위와 한계

## 사용 데이터의 역할

| 데이터 | 프로젝트 내 용도 |
|---|---|
| PlantSeg | 병변 분할과 질병 분류의 핵심 이미지·마스크 |
| PlantWild healthy | 정상 잎 hard negative와 오탐 평가 |
| 농사로/NCPMS | 증상, 발생 조건, 예방·방제 근거 |
| 한국식물병명목록 | 병명 표준화와 동의어 정리 |
| ADP 계열 자료 | 질병 설명 근거 보강 |
| 직접 기록한 실패 사례 | 배경·정상 조직 false positive 개선 |

## 빈 마스크 해석

빈 마스크는 두 종류로 나뉩니다.

1. **PlantSeg 비정상 빈 마스크 16건:** 병변 분류 crop을 만들 수 없어 제외한 데이터 품질 문제
2. **PlantWild 빈 마스크 4,000건:** 정상 잎에는 병변이 없다는 의도된 정답

따라서 “빈 마스크 총 4,016건이 오류”라고 표현하면 안 됩니다. 오류로 제외한 것은 16건이고, 4,000건은 정상 음성 샘플입니다.

## 클래스 불균형

PlantSeg를 정규화했을 때 386개 클래스 중 273개가 10장 미만, 284개가 30장 미만이었습니다. 이 때문에 모든 질병을 동일한 신뢰도로 다루는 대신 다음 전략을 사용했습니다.

- 24개 주요 작물로 제품 범위 제한
- 학습 가능한 질병 62개 클래스로 정리
- Macro Recall을 평가 지표로 사용
- Top-3 후보 유지
- 사용자가 작물을 선택하는 host constraint
- 검색 근거가 부족한 경우 확정 표현 억제

## GitHub에 데이터를 포함하지 않은 이유

- 원본 데이터셋의 재배포 조건을 별도로 확인해야 함
- 모델 가중치와 이미지 데이터 용량이 큼
- 공공 API에서 수집한 원문도 출처별 이용 조건이 다름
- `.env`, 터널 주소, 로컬 경로에는 민감정보가 들어갈 수 있음

대신 데이터 규모, 정제 기준, split, 지표 원본 JSON/CSV, RAG manifest와 감사 결과를 남겨 구현과 판단 근거를 설명합니다.

## 의료·농업적 한계

이 프로젝트는 시각적 의사결정 보조 도구입니다. 다음 조건에서는 결과의 신뢰도가 낮아질 수 있습니다.

- 데이터에 없는 작물이나 질병
- 영양 결핍, 약해, 냉해 등 비생물성 스트레스
- 여러 질병이 동시에 발생한 이미지
- 병변이 너무 작거나 흔들린 사진
- 잎 뒷면·줄기·열매처럼 학습 분포와 다른 부위
- 유사 증상을 보이는 초기 단계 질병

실제 방제나 약제 사용은 지역 농업기술센터, 전문가, 등록 약제 정보와 함께 확인해야 합니다.

## 재현성 한계

현재 저장소는 포트폴리오용 공개본입니다. 대용량 데이터와 체크포인트가 없어 처음부터 같은 결과를 완전 재현하는 패키지는 아닙니다. 완전 재현 저장소로 발전시키려면 다음이 추가되어야 합니다.

- 데이터 다운로드 및 라이선스 확인 절차
- 정제 결과 manifest와 checksum
- 모든 Python/Dart 의존성 lock
- 모델 다운로드 또는 release artifact
- 학습 명령과 seed, 하드웨어 기록
- 자동 평가 스크립트와 기대 결과 범위
