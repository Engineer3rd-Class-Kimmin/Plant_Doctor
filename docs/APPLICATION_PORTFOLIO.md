# 잎파라치: 문제, 기여, 결과와 검증 범위

잎 사진에서 질병 후보를 찾는 것과 사용자가 근거를 보고 판단할 수 있게 하는 것은 별개의 문제였다. 병변을 먼저 분할하고, 작물 범위 안에서 후보를 좁힌 다음, 농업 자료에서 설명 근거를 찾도록 구성했다.

## 내가 맡은 일과 선택한 방법

이 공개본에 정리된 작업은 개인 프로젝트다. 데이터 정제, SegFormer-B3와 ConvNeXt-Small 학습, RAG 수집·검색·출처 검사, FastAPI 서버, Flutter 앱을 연결했다. 자세한 흐름과 시행착오는 [개발 과정](DEVELOPMENT_JOURNEY.md)에 남겼다.

배경을 질병으로 인식하는 문제 때문에 전체 이미지 분류 대신 병변 분할과 분류를 나눴다. 정상 잎을 hard negative로 포함했고, 분류 Top-3 후보를 유지했다. 모델 확률만으로 방제 설명을 만들지 않도록 검색 근거와 출처를 연결했다. 이는 확정 진단이나 약제 사용의 정확성을 보증하지 않는다.

## AI를 사용한 범위와 검증

제품의 AI는 병변 분할, 질병 후보 분류, 임베딩 검색과 LLM 기반 구조화 설명에 사용된다. 이는 개발 과정에서 코딩 도구를 사용한 범위와 구분한다. 과거 전체 개발에서 도구별 생성량과 수동 수정량을 추적한 기록은 없다.

이번 포트폴리오 문서, 신규 평가셋과 실행기는 Codex로 작성했다(ai-assisted). 결과는 정답 문장을 모델에게 다시 평가하게 하지 않고, 공개 원본 코드의 함수를 실제 실행해 기대값과 비교했다. 실행기에서는 무거운 모델 import와 외부 API 호출을 피하기 위해 AST로 네 함수와 필요한 상수만 읽었다. 해당 함수의 코드 본문은 수정하지 않았다. 이 방식은 함수 단위 검증이며 서버 통합 검증은 아니다.

## 결과와 한계

| 평가 | 확인한 결과 | 해석 범위 |
|---|---|---|
| 기존 B3 분할 | Dice 80.26%, IoU 67.03% | 기존 PlantSeg 테스트 산출물. 이번에 이미지를 다시 추론한 결과가 아님 |
| 기존 Small 분류 | Top-1 82.72%, Top-3 93.11% | 기존 검증 결과. 모델 선택에 사용된 검증 지표이며 독립 현장 테스트로 해석하지 않음 |
| 신규 공개 코드 계약 | 23건 중 22건 통과, 1건 실패 | 라벨·작물명·JSON·빈 값 처리. 모델 정확도와 합산하지 않음 |

새 평가에서 `napa_cabbage_rot`의 기대 host는 `napa_cabbage`였지만 실제로 `napa`를 반환했다. 복합 작물명이 host 정합성에 미치는 문제를 확인했으며, 원본 코드를 고친 결과처럼 꾸미지 않았다. [평가셋·입력별 결과·재현 명령](../evaluation/contract-v1/RESULTS.md)과 [JSON 원본](../evaluation/contract-v1/results.json)을 함께 제공한다.

모델 지표 원본은 [분할](../evidence/segmentation/best_metrics.json), [분류](../evidence/classification/epoch_021.json)에 있다. [기존 평가 조건](MODEL_EVALUATION.md)과 [공개 범위·한계](DATA_AND_LIMITATIONS.md)를 함께 확인해야 한다. RAG 인덱스의 무결성과 출처 감사는 검색 정답률·생성 사실성의 독립 평가가 아니다. 실제 농가 외부셋, 전문가 정답 기반 RAG 평가, 모바일 전체 흐름의 정량 결과는 이 신규 평가에 포함하지 않았다.

## 공개 자료의 범위

원본 이미지, 모델 가중치, 사용자 사진, API 키, 전체 대화 기록은 추가로 공개하지 않았다. 실행 결과에는 합성 문자열과 기대값, 코드·평가셋·실행기 해시만 넣었다. 기존 공개 파일의 전체 보안 감사를 완료했다는 뜻은 아니다.
